
# 人工智能专班任务与成果跟踪小工具模块详细需求说明

## 一、文档说明

本文档用于指导人工智能专班任务与成果跟踪小工具的具体开发，作为前后端开发、接口设计、页面设计、测试验收和后续迭代的统一需求依据。

系统面向人工智能专班内部约15名成员使用，核心目标是支撑“周计划、周交付、周评价”管理闭环，并进一步通过周报分析、成果库沉淀、统计导出等功能，为专班管理、工作量统计和领导汇报提供数据支撑。

系统采用轻量化建设方式，不做复杂权限体系，不做正式绩效考核平台，不建设多级审批流程。第一版重点实现可用、稳定、易维护的最小闭环功能。

---

## 二、总体功能范围

| 模块 | 功能定位 | 第一版是否必须 |
|---|---|---|

| 周评价管理 | 对任务交付质量进行评价并形成积分记录 | 必须 |

## 三、首页看板模块

## 3.1 模块目标

首页看板用于让专班负责人和成员快速了解当前周工作推进情况，包括任务总量、完成情况、延期情况、待评价任务、成员积分排行和近期截止任务等。首页不追求复杂图表，应以清晰、直观、便于汇报为原则。

## 3.2 使用对象

| 使用对象 | 使用目的 |
|---|---|
| 专班负责人 | 掌握本周任务推进状态，发现延期和未评价事项 |
| 任务牵头人 | 查看待评价任务和协作任务状态 |
| 普通成员 | 查看个人任务、截止时间和完成情况 |
| 管理人员 | 快速掌握专班整体运行情况 |

## 3.3 功能点

### 3.3.1 本周总体统计

首页顶部展示本周核心指标卡片。

| 指标 | 说明 |
|---|---|
| 本周任务总数 | 当前周次下所有任务数量 |
| 已完成任务数 | 状态为“已完成”的任务数量 |
| 进行中任务数 | 状态为“未开始”“进行中”的任务数量 |
| 已提交待评价数 | 状态为“已提交”但未完成评价的任务数量 |
| 需修改任务数 | 状态为“需修改”的任务数量 |
| 延期任务数 | 超过截止时间且未完成的任务数量 |

### 3.3.2 任务状态分布

展示本周任务在不同状态下的分布，形式可以是柱状图、环形图或简单列表。第一版建议优先使用简单图表和数字列表，避免复杂交互。

### 3.3.3 个人积分排行

展示本周个人积分排行和累计积分排行。

| 字段 | 说明 |
|---|---|
| 排名 | 根据积分排序 |
| 姓名 | 成员姓名 |
| 所属单位 | 成员所属单位 |
| 本周积分 | 当前周次获得积分 |
| 累计积分 | 系统内累计积分 |
| 优秀任务数 | 当前周获得优秀评价的任务数量 |

### 3.3.4 待评价任务列表

展示所有已提交但未评价的任务，便于负责人及时处理。

| 字段 | 说明 |
|---|---|
| 任务名称 | 待评价任务 |
| 责任人 | 任务责任人 |
| 提交时间 | 最近一次成果提交时间 |
| 截止时间 | 任务原定截止时间 |
| 操作 | 进入评价页面 |

### 3.3.5 临近截止与延期任务

展示距离截止时间较近的任务和已延期任务。

| 类型 | 说明 |
|---|---|
| 临近截止任务 | 距离截止时间小于等于2天，且未完成 |
| 已延期任务 | 当前时间超过截止时间，且任务状态不是已完成 |

## 3.4 页面交互要求

1. 默认展示当前周数据。
2. 支持选择其他周次查看历史数据。
3. 点击统计卡片可跳转到对应筛选后的任务列表。
4. 点击待评价任务可进入评价页面或任务详情页。
5. 首页数据应来自后端统计接口，不在前端自行复杂计算。

## 3.5 验收标准

| 验收项 | 标准 |
|---|---|
| 数据准确性 | 首页各项统计与任务列表数据一致 |
| 周次切换 | 可切换周次并刷新统计结果 |
| 待评价任务 | 已提交未评价任务能够正确展示 |
| 延期识别 | 超期未完成任务能够正确展示 |
| 页面风格 | 与 `example.html` 保持整体风格一致 |

## 四、人员管理模块

## 4.1 模块目标

人员管理用于维护专班成员基础信息，是任务分配、评价统计、周报分析和成果归属的基础数据来源。第一版不做复杂组织权限，仅维护专班成员信息和能力标签。

## 4.2 功能点

### 4.2.1 人员列表

展示所有专班成员信息。

| 字段 | 说明 |
|---|---|
| 姓名 | 专班成员姓名 |
| 所属单位 | 成员来源单位 |
| 联系方式 | 手机号、邮箱或其他联系方式 |
| 能力标签 | 方案编制、模型训练、Prompt设计、前端开发等 |
| 是否骨干 | 标记是否为骨干人员 |
| 状态 | 在用、停用 |
| 创建时间 | 人员记录创建时间 |

### 4.2.2 新增人员

支持新增专班成员，至少填写姓名和所属单位。能力标签可多选。

### 4.2.3 编辑人员

支持修改成员所属单位、联系方式、能力标签、是否骨干、状态等。

### 4.2.4 停用人员

第一版建议采用“停用”而不是物理删除。停用人员不再参与新任务分配，但历史任务、评价、成果记录仍保留。

### 4.2.5 能力标签

能力标签用于后续任务分配和人员画像。

建议内置标签如下：

| 标签 | 说明 |
|---|---|
| 方案编制 | 能承担方案、汇报、制度等材料编制 |
| 材料撰写 | 能承担文字材料整理和优化 |
| 数据治理 | 能承担数据清洗、标准化、样本整理 |
| 模型训练 | 能承担模型训练、调参、验证 |
| 模型评测 | 能承担模型效果评估和测试 |
| Prompt设计 | 能承担提示词设计和大模型任务编排 |
| 前端开发 | 能承担前端页面开发 |
| 后端开发 | 能承担后端接口和数据库开发 |
| 系统测试 | 能承担功能测试和问题记录 |
| 项目管理 | 能承担任务组织、协调和进度跟踪 |

## 4.3 查询筛选要求

| 筛选项 | 说明 |
|---|---|
| 姓名 | 支持模糊查询 |
| 所属单位 | 支持按单位筛选 |
| 能力标签 | 支持按标签筛选 |
| 是否骨干 | 支持筛选骨干成员 |
| 状态 | 支持筛选在用、停用 |

## 4.4 数据规则

1. 姓名不能为空。
2. 所属单位不能为空。
3. 停用人员不应出现在新建任务的责任人默认选择列表中。
4. 历史任务中的人员引用不得因人员停用而丢失。
5. 人员删除建议第一版不开放，避免影响统计数据完整性。

## 4.5 验收标准

| 验收项 | 标准 |
|---|---|
| 新增人员 | 能正确新增并展示在人员列表 |
| 编辑人员 | 能正确修改人员信息 |
| 停用人员 | 停用后不影响历史数据 |
| 标签筛选 | 能按能力标签筛选人员 |
| 任务引用 | 人员能被任务模块选择和引用 |

## 五、基础字典模块

## 5.1 模块目标

基础字典用于统一系统中的任务类型、任务状态、任务难度、评价等级、能力标签、成果类型等选项，避免前后端写死不一致。

第一版可以采用后端固定字典接口，也可以在数据库中建立字典表。考虑开发效率，第一版建议后端提供固定字典接口，后续再扩展为可维护配置。

## 5.2 字典类型

| 字典 | 值 |
|---|---|
| 任务类型 | 重点攻关任务、支撑服务任务、能力提升任务、临时协同任务 |
| 任务难度 | 低、中、高 |
| 任务状态 | 未开始、进行中、已提交、需修改、已完成、已延期 |
| 评价等级 | 优秀、合格、需修改、不合格 |
| 成果类型 | 方案材料、技术报告、测试记录、模型评估、Prompt模板、代码工具、案例分析、学习材料 |
| 人员状态 | 在用、停用 |
| 是否骨干 | 是、否 |

## 5.3 接口要求

建议提供统一字典接口：

```text
GET /api/dictionaries
GET /api/dictionaries/{type}
```

返回结构应便于前端直接渲染下拉框。

## 5.4 验收标准

| 验收项 | 标准 |
|---|---|
| 字典统一 | 前端下拉选项均来自统一字典 |
| 值一致 | 前端展示值与后端保存值一致 |
| 可扩展 | 后续能够平滑扩展为数据库配置 |

## 六、任务管理模块

## 6.1 模块目标

任务管理是系统核心模块，用于实现任务创建、分配、推进、提交、评价和关闭。该模块应支撑每周任务安排和个人贡献统计，是后续周报分析、成果库和工作量统计的基础。

## 6.2 任务状态流转

建议任务状态如下：

```text
未开始 → 进行中 → 已提交 → 已完成
                      ↘ 需修改 → 已提交 → 已完成
```

延期状态可由系统根据截止时间自动识别，也可以在任务状态中保留“已延期”。建议第一版采用“状态字段 + 是否延期计算”的方式，避免状态混乱。

| 状态 | 含义 |
|---|---|
| 未开始 | 任务已创建但尚未启动 |
| 进行中 | 任务正在处理 |
| 已提交 | 成员已提交成果，等待评价 |
| 需修改 | 评价后认为需要修改完善 |
| 已完成 | 评价通过，任务闭环 |
| 已延期 | 超过截止时间仍未完成，可由系统计算或人工标记 |

## 6.3 任务字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 任务名称 | 是 | 简明描述任务 |
| 任务描述 | 否 | 任务背景、具体要求 |
| 任务类型 | 是 | 重点攻关、支撑服务、能力提升、临时协同 |
| 任务难度 | 是 | 低、中、高 |
| 责任人 | 是 | 主责成员 |
| 协作人 | 否 | 可多选 |
| 所属周次 | 是 | 任务归属周 |
| 截止时间 | 是 | 任务完成截止日期 |
| 交付物要求 | 是 | 明确需要提交什么成果 |
| 当前状态 | 是 | 默认未开始 |
| 创建人 | 否 | 可记录任务创建者 |
| 创建时间 | 自动 | 系统生成 |
| 更新时间 | 自动 | 系统更新 |

## 6.4 任务列表

任务列表用于集中查看任务。

### 6.4.1 列表字段

| 字段 | 说明 |
|---|---|
| 任务名称 | 支持点击进入详情 |
| 任务类型 | 显示任务分类 |
| 任务难度 | 显示低、中、高 |
| 责任人 | 显示主责人员 |
| 协作人 | 显示协作人员 |
| 所属周次 | 显示任务归属周 |
| 截止时间 | 显示计划完成时间 |
| 状态 | 显示当前状态 |
| 是否延期 | 根据截止时间和状态判断 |
| 操作 | 查看、编辑、提交成果、评价等 |

### 6.4.2 查询筛选

| 筛选项 | 说明 |
|---|---|
| 关键词 | 按任务名称、描述模糊查询 |
| 周次 | 查看某一周任务 |
| 责任人 | 查看某人任务 |
| 任务类型 | 按任务类型筛选 |
| 任务状态 | 按状态筛选 |
| 是否延期 | 查看延期任务 |
| 任务难度 | 按难度筛选 |

## 6.5 新建任务

新建任务时必须明确：

1. 任务名称；
2. 任务类型；
3. 任务难度；
4. 责任人；
5. 所属周次；
6. 截止时间；
7. 交付物要求。

保存后任务默认为“未开始”。

## 6.6 编辑任务

未完成任务允许编辑。已完成任务原则上不建议随意编辑，如必须编辑，应保留更新时间。第一版可以暂不做操作日志，但后续建议增加。

## 6.7 删除任务

第一版建议仅允许删除尚未产生交付和评价的任务。已经有成果或评价的任务不允许删除，可以标记为作废或停用。

## 6.8 任务详情

任务详情页应展示以下内容：

| 区域 | 内容 |
|---|---|
| 基本信息 | 任务名称、类型、难度、责任人、协作人、周次、截止时间、状态 |
| 任务要求 | 任务描述、交付物要求 |
| 成果记录 | 成果名称、说明、链接、提交人、提交时间 |
| 评价记录 | 评价等级、评价意见、积分、评价人、评价时间 |
| 操作区 | 编辑、更新状态、提交成果、评价、返回列表 |

## 6.9 验收标准

| 验收项 | 标准 |
|---|---|
| 任务创建 | 能创建完整任务并展示在列表 |
| 任务查询 | 支持按周次、人员、状态等筛选 |
| 状态流转 | 能完成未开始、进行中、已提交、需修改、已完成流转 |
| 延期识别 | 超过截止时间未完成任务能被识别 |
| 详情展示 | 能完整展示任务、成果、评价信息 |
| 数据关联 | 能关联人员、周次、成果、评价等数据 |

## 七、周计划管理模块

## 7.1 模块目标

周计划管理用于按周组织专班工作，将任务安排从零散口头安排转变为可查看、可追踪、可评价的周计划。该模块是“周计划、周交付、周评价”闭环的入口。

## 7.2 周次字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 周次名称 | 是 | 如“2026年第19周”或“5月第1周” |
| 开始日期 | 是 | 周开始日期 |
| 结束日期 | 是 | 周结束日期 |
| 状态 | 是 | 当前周、历史周、未开始 |
| 备注 | 否 | 特殊说明 |

## 7.3 功能点

### 7.3.1 创建周次

系统支持创建周次。第一版可以手动创建周次，后续可自动按日期生成。

### 7.3.2 当前周识别

首页和任务默认展示当前周数据。当前周可以根据日期自动判断，也可以由管理员手动设置。第一版建议采用日期自动判断。

### 7.3.3 周计划查看

按周展示所有任务安排。

| 字段 | 说明 |
|---|---|
| 序号 | 自动生成 |
| 任务名称 | 当前周任务 |
| 任务类型 | 分类展示 |
| 责任人 | 主责人员 |
| 协作人 | 协作人员 |
| 截止时间 | 完成期限 |
| 交付要求 | 需要提交的成果 |
| 当前状态 | 任务状态 |
| 是否延期 | 是否超期 |

### 7.3.4 按人员查看周任务

展示每名成员本周承担的任务数量和任务清单。

### 7.3.5 复制上周未完成任务

支持将上一周未完成任务复制到当前周，或将任务延续到当前周。第一版可以简化为“手动重新创建”，如开发时间允许再实现复制功能。

## 7.4 验收标准

| 验收项 | 标准 |
|---|---|
| 周次创建 | 能创建周次并关联任务 |
| 当前周展示 | 首页和任务模块能默认读取当前周 |
| 周计划表 | 能按周展示任务安排 |
| 人员视图 | 能查看每个人本周任务 |
| 导出支持 | 周计划能够导出为Excel |

## 八、成果提交模块

## 8.1 模块目标

成果提交用于记录成员完成任务后的实际交付内容，解决成果分散、难追踪、难复用的问题。第一版采用“成果说明 + 成果链接”的轻量方式，不做附件上传。

## 8.2 成果字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 任务ID | 是 | 关联任务 |
| 成果名称 | 是 | 成果标题 |
| 成果说明 | 是 | 对成果内容进行简要说明 |
| 成果链接 | 否 | 网盘、GitHub、文档、系统地址等 |
| 成果类型 | 否 | 方案材料、代码工具、测试记录等 |
| 提交人 | 是 | 默认当前任务责任人或提交人 |
| 提交时间 | 自动 | 系统记录 |
| 修改说明 | 否 | 重新提交时填写 |

## 8.3 功能点

### 8.3.1 提交成果

成员在任务详情页提交成果。提交后任务状态变为“已提交”。

### 8.3.2 修改成果

对于“需修改”的任务，成员可以重新提交成果并填写修改说明。系统保留历史提交记录。

### 8.3.3 查看成果历史

任务详情页展示所有提交记录，按提交时间倒序排列。

### 8.3.4 成果链接校验

第一版可以不做复杂校验，但应保证链接字段长度足够，支持内部文档、网盘、Git仓库等多种地址。

## 8.4 状态联动

| 操作 | 状态变化 |
|---|---|
| 首次提交成果 | 任务状态变为已提交 |
| 需修改后重新提交 | 任务状态由需修改变为已提交 |
| 评价合格或优秀 | 任务状态变为已完成 |
| 评价不合格或需修改 | 任务状态变为需修改或不合格记录 |

## 8.5 验收标准

| 验收项 | 标准 |
|---|---|
| 成果提交 | 能填写成果名称、说明、链接并保存 |
| 状态联动 | 提交成果后任务状态正确变化 |
| 历史记录 | 多次提交能够保留历史记录 |
| 详情展示 | 任务详情中能查看成果记录 |
| 成果库关联 | 已完成成果能被成果库查询 |

## 九、周评价管理模块

## 9.1 模块目标

周评价管理用于对已提交任务进行质量评价，并形成积分记录。该模块不作为正式绩效处罚工具，而是作为专班内部贡献记录和任务质量跟踪依据。

## 9.2 评价对象

评价对象为已经提交成果的任务。未提交成果的任务不能评价。

## 9.3 评价字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 任务ID | 是 | 被评价任务 |
| 评价等级 | 是 | 优秀、合格、需修改、不合格 |
| 评价意见 | 是 | 对成果质量的具体意见 |
| 基础积分 | 是 | 根据评价等级自动生成 |
| 加分积分 | 否 | 高难度、重点任务等加分 |
| 最终积分 | 自动 | 基础积分 + 加分积分 |
| 评价人 | 是 | 评价操作人 |
| 评价时间 | 自动 | 系统记录 |

## 9.4 积分规则

建议规则如下：

| 评价等级 | 基础积分 | 状态变化 |
|---|---:|---|
| 优秀 | 3 | 已完成 |
| 合格 | 2 | 已完成 |
| 需修改 | 1 | 需修改 |
| 不合格 | 0 | 需修改或保留不合格记录 |

加分规则：

| 加分项 | 分值 |
|---|---:|
| 高难度任务 | +1 |
| 重点攻关任务 | +1 |
| 成果可复用价值高 | +1 |

第一版建议加分项由评价人手动填写，系统不自动复杂判断。

## 9.5 功能点

### 9.5.1 待评价任务列表

展示所有状态为“已提交”的任务。

### 9.5.2 填写评价

评价人选择评价等级，填写评价意见和加分项。

### 9.5.3 评价后状态更新

评价保存后，根据评价等级更新任务状态。

### 9.5.4 评价记录查看

任务详情页展示评价记录。第一版每个任务可以只保留最新一次评价，也可以保留多次评价记录。建议保留多次评价记录，便于闭环追踪。

## 9.6 验收标准

| 验收项 | 标准 |
|---|---|
| 待评价列表 | 已提交任务能进入待评价列表 |
| 评价保存 | 能保存等级、意见、积分 |
| 积分计算 | 最终积分计算正确 |
| 状态变化 | 评价后任务状态正确更新 |
| 记录追踪 | 任务详情能查看评价记录 |

## 十一、大模型周报分析模块

## 11.1 模块目标

大模型周报分析用于对成员提交的周报内容进行结构化抽取和智能分析，辅助识别工作成果、任务闭环情况、风险问题和下周计划。该模块不是为了替代人工评价，而是为负责人提供辅助分析结果。

## 11.2 功能定位

| 功能 | 说明 |
|---|---|
| 周报录入 | 成员填写或粘贴个人周报 |
| 结构化抽取 | 从周报中抽取工作事项、成果、问题、计划 |
| 任务匹配 | 将周报内容与系统任务记录进行交叉核验 |
| 贡献摘要 | 自动生成个人贡献摘要 |
| 风险提示 | 识别延期、成果缺失、描述不一致等问题 |
| 专班周报草稿 | 汇总多人成果生成专班周报初稿 |

## 11.3 周报录入字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 周次 | 是 | 周报所属周 |
| 成员 | 是 | 周报提交人 |
| 本周工作 | 是 | 本周完成事项 |
| 主要成果 | 否 | 明确成果和交付物 |
| 存在问题 | 否 | 工作阻塞、风险、困难 |
| 下周计划 | 否 | 下一步计划 |
| 原始文本 | 是 | 保留完整周报原文 |
| 提交时间 | 自动 | 系统记录 |

## 11.4 分析输出结构

大模型分析结果建议采用结构化JSON保存，同时前端以卡片形式展示。

| 输出项 | 说明 |
|---|---|
| 本周主要工作 | 从周报中提取实际完成的工作事项 |
| 对应系统任务 | 与任务管理模块中的任务进行匹配 |
| 成果交付情况 | 判断是否存在明确成果 |
| 工作质量判断 | 从完整性、清晰度、可复用性角度判断 |
| 存在问题 | 提取延期、阻塞、协作不足、描述不清等问题 |
| 下周计划 | 提取下周计划事项 |
| 候选任务 | 可转为下周任务的事项 |
| 贡献摘要 | 生成适合汇报使用的个人贡献表述 |
| 风险提示 | 识别任务未闭环、成果缺失、周报与任务不一致等问题 |

## 11.5 任务交叉核验规则

系统应将周报内容与任务数据进行对比，辅助发现以下情况：

| 情况 | 说明 |
|---|---|
| 周报提到但系统无任务 | 可能存在未纳入管理的工作 |
| 系统有任务但周报未提及 | 可能存在任务未反馈 |
| 周报称已完成但未提交成果 | 可能存在成果缺失 |
| 任务已延期但周报未说明 | 可能存在风险未反馈 |
| 周报描述过于笼统 | 无法判断实际产出 |

## 二十一、开发注意事项

1. 所有业务数据统一进入MySQL，不使用本地临时文件保存关键数据。
2. 所有代码、文档、配置均放在 `ai_team_task_platform` 目录下。
3. 第一版不追求大而全，优先完成任务闭环。
4. 页面风格参考 `example.html`，保持简洁、清晰、适合汇报。
5. 大模型分析结果必须结构化保存，不能只在页面临时展示。
6. 周报分析结果仅作为辅助判断，不直接作为正式考核结论。
7. 统计和导出必须基于数据库真实记录生成。
8. 提交代码前必须确认未提交 `node_modules`、`dist`、`.venv`、日志、数据库文件等无关内容。
9. 每个模块开发完成后，应补充必要的接口说明或测试说明。
10. 所有功能应服务于“周计划、周交付、周评价、周统计、周报分析”主线，不做偏离主线的复杂扩展。
